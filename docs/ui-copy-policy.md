# 사용자 화면 문구 기준

2026-10-27 실기기 QA에서 사용자가 정한 제품 방향이다. 이전 문서의 미확인 경고·추천 근거·정렬 원리 노출 요구보다 이 기준을 우선한다. 과거 검사 기록은 당시 상태를 설명하며 새 화면 요구사항이 아니다.

## 화면에 남길 것

- 장소 이름, 종류, 주소, 코스의 방문 순서와 개수.
- 거리 값은 필요한 곳에 `직선거리 약 3.2 km`처럼 짧게 표시한다. 실제 이동거리·시간으로 바꿔 부르지 않는다. 값이 없으면 설명 문장을 추가하지 않고 생략한다.
- 추천·저장·지도·조건 수정처럼 사용자가 바로 할 수 있는 행동.
- 실제 실패 때는 문제와 다음 행동을 한두 문장으로 알린다. 예: `코스를 만들 장소가 부족해요. 활동이나 출발점·이동수단을 바꿔주세요.`
- 진행하려면 선택이 필요한 경우에만 짧게 묻는다. 일반 해석 확인을 매번 반복하지 않는다.

## 화면에서 뺄 것

- `번호: 가까운 다음 장소 순`, `점수 순위 아님`, AI 비교 순서 등 번호·정렬 원리 설명.
- `취향 일치 미확인`, `검증된 블로그 태그 없음`, 근거 부족·현장 확인 시각 등 진단 경고.
- AI 후보 비교 실패, 규칙 대체, 카테고리·인기도·거리 계산 방식과 내부 계약 설명.
- 후보 수 합산 주의, 단계별 후보 통계, 등록 장소 기준 등 개발·검수용 단서.
- 지도 열기 직전의 반복적인 좌표 미확인 경고와 이미 선택한 내용을 다시 승인하는 확인창.

이 정보는 응답 메타데이터·기존 저장 데이터·로그·QA 기록에 남긴다. 경고를 숨겼다는 이유로 조용함, 데이트 적합성, 영업, 정확한 좌표 등을 새로 보장하지 않는다. 데이터 검증과 후보 제한, 중복 실행 방지, 저장 보존 동작은 유지한다.

## 화면별 적용

| 화면 | 표시 기준 |
|---|---|
| 입력·태그 | 선택 항목과 간단한 변경 확인. 내부 해석·원문 우선순위 설명 생략 |
| 스팟·코스·저장 | 장소와 행동 중심. 경고·정렬 방식·처리 방식 배너 생략 |
| 코스 비교 | 방문 목록, 장소 수, 필요한 거리, 현재 코스와 다른 장소 수 |
| 추천 부족 | 부족한 활동 또는 장소 수 문제와 수정 행동. 후보 통계 생략 |
| 지도 | 바로 열기. 좌표 사용 제한은 내부에서 유지하고 실제 열기 실패 때만 짧게 안내 |
| 저장·태그 오류 | 다시 시도/직접 선택 등 필요한 행동만 안내 |

## 이번 기획 채팅 작업 범위

코스 비교·코스 부족·공통 오류 문구·지도 경고·기존 진단 위젯 및 위 기준과 충돌하던 기획/검수 문서를 정리했다. 결과·저장 화면과 태그 확인창은 별도 공동 QA 채팅이 수정한다. 그 채팅에서 전체 최종 검사와 APK 빌드·설치를 합쳐 진행한다. 이 문서만으로 실기기 반영 완료나 U12 해결을 뜻하지 않는다.
