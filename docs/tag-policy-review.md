고정 소스의 관련 7개 기존 테스트 파일을 임시 소스/DB 복사본에서 직접 실행: **197 passed**, 코어수 탐지 warning1. 이 통과로 위 결함이 해소됐다고 판정하지 않았다. 별도 실제 DB API 15개 시나리오와 분류 반례를 기록했다. AI 출력은 주입한 모의 JSON 또는 차단함수이며 실제 모델 정확도 시험은 아니다. 네트워크·dotenv 로드를 차단했고 네이버/외부 키를 읽거나 사용하지 않았다.

## 1차 후보 정책

1. 요청을 종류/시설주목적, 동행, 환경조건, 분위기선호, 명시제외, 순서, 수량으로 분리한다. 자동태그는 요약 제안이며 원문에서 없던 아이·술·시설목적을 생성하지 않는다. 식사→쇼핑→카페와 산책→야장은 각각 순차 단계다. 한 단계의 대안 OR와 순차 AND를 구분한다.
2. 입력의 공백/Unicode를 정규화하고 원문·원분류를 보존한다. 공급자별 분류의 전체 경로/leaf를 승인된 사전에 매핑한다. `등산,아웃도어`, `키즈카페,실내놀이터` 같은 복합값을 무작정 일반 단어로 쪼개거나 단순 포함문자로 판정하지 않는다. 정확한 소매 leaf/시설 leaf와 검토된 계층 관계를 사용한다.
3. 내부에는 별도 `venue_kind`, `primary_purpose`, `audience_scope`, `visit_access`, `environment`, `evidence`를 둔다. 등산시설과 등산용품 소매, 국가유산과 국가유산청, 카페휴식과 보드게임, 공방제조·판매·체험을 분리한다. `unknown`은 false와 다르다. 복합시설은 근거 있는 복수 목적만 허용한다.
4. 필터 순서: 지역/신원 보류/좌표 → 명시 제외 → 시설종류·주목적 → 동행별 아동 gate → 필수조건의 충족/미충족/미확인 분리 → 반경/방문중복 → 단계별 전체 후보수 → 한정된 AI 비교 후보. 현행과 물리적 순서가 달라도 각 단계 분모와 이유를 보존한다. AI는 적격 후보 안에서만 선택하고 반환 ID/단계/제외/방문중복을 재검사한다.
5. 이름은 보조 단서다. 정확한 ‘보드게임카페’처럼 시설목적 전체 표현과 카페분류가 결합되면 목적 단서로 쓸 수 있다. ‘보드’, ‘라이브러리’, 브랜드명만으로 배제하지 않는다. `연구소전시관`을 연구소라는 단어만으로 전부 배제하지 않고 실제 전시시설 근거/보류 ID를 확인한다. 분류와 이름이 충돌하는 PC방 레코드는 미확인으로 보류한다.
6. 정규화/필터 결과에는 정책버전, 분류원문, 매핑근거, 제외/보류 사유, 장소 ID를 둔다. 검색수집어 `search_category`는 발견 단서이며, 실제 분류가 비었다고 곧바로 그 종류가 입증되지는 않는다. 타입 미확인 후보를 자동채움에 쓰지 않는다.
7. 분위기·영업·야장·허용연령·사진·야경·예약·접근성은 이름/인기도/모델 상식으로 충족 처리하지 않는다. 현재 DB의 영업시간 텍스트/과거 블로그도 당일 영업의 검증으로 승격하지 않는다. 취향 증거와 운영 사실 증거를 별도 필드로 보관한다.

현재 자연어 AI 비교 프롬프트에는 선호 이름이 전달되지만 후보의 해당 성질 근거는 전부 미확인이다. 근거 없는 조용함을 ‘충족’이라 쓰지 않는 것에 더해, 선호 이름만 보고 장소 이름에서 추측해 순위를 매기지 않게 해야 한다. 요청 선호는 보존하되 비교에 사용한 속성/미사용 속성과 이유를 분리하고, 현재는 입증된 종류·직선거리 등 제공 근거만 비교한다.

### 충돌·부정·동의 공통규칙

- P1 동행: **직접 선택한 동행 > 문장 동행 > 자동 제안**. 가족/부모님/친구/연인/실내는 아동의 증거가 아니다. 직접 아이동반은 허용 gate를 열 뿐 일반 카페 종류를 바꾸지 않는다. 수동 친구와 문장 아이동반 충돌은 수동우선 내용을 보여주고, 명시 키즈시설 활동은 별도 의도로 판단한다.
- P2 분위기: 직접 수정은 같은 속성에만 우선한다. 직접 조용한 태그를 골랐다고 문장의 시원한 맥주나 여유로움 등 다른 필드를 지우지 않는다. 조용함↔활기참이 충돌하면 단계/범위 확인을 받는다. ‘활동적인’을 ‘시끄러운’의 동의어로 고정하지 않는다.
- P3 종류/순서: 직접 코스 순서/수량과 확정 지역·교통을 우선하되 명시제외는 계속 유지한다. 수동 카페 슬롯과 ‘카페 말고’가 충돌하면 자동변환하지 말고 어느 설정을 바꿀지 보인다. 단일 단계에서 식사+전시 태그가 충돌하면 여러 장소 방문인지 대안인지 구분한다.
- P4 환경: ‘실내 위주’는 선호, ‘반드시 실내’나 ‘야장’은 필수조건으로 해석한다. 야외는 야외좌석/야경과 다르다. 미확인 대안 보기 동의는 해당 증거미확인만 허용하며 시설목적·명시제외·아동 gate·반경을 풀지 않는다.
- 모든 행에서 부정 범위를 보존한다. ‘카페 말고’, ‘키즈카페 말고 카페’, ‘카페 말고는 안 가’, ‘카페가 아닌 곳은 싫다’, ‘아이 없이’, ‘키즈카페 근처 카페’를 다르게 다룬다. 일반 카페와 명시 보드카페의 목적 구분을 유지해 기존 alias/부정 회귀를 깨지 않는다.

## 전체 현행 47개 태그 매트릭스

각 행의 내부값은 기존 API/저장값이다. 표시명을 바꿔도 즉시 내부값을 갈아끼우지 않는다. 원문 ‘부모님과’ 등은 기존 내부값으로 alias 처리한다. 매트릭스의 성격/허용/제외는 **권장 정책**, R 경로는 **현재 구현**이다. 기계판 `policy_matrix.json`에는 각 행별 S/M/D/A 4경로와 권장 경로 전체를 풀어 기록했다.

근거 E-K=정규분류+시설목적, E-S=출처/시점 있는 취향근거, E-V=해당 시설·운영 필드 근거, E-C=동행 원문/직접선택(시설편의 별도), E-N=야간조망/접근/시간 근거, E-P=촬영대상/촬영가능 근거. 현재 verified 태그는0이다.

U-K=종류/목적 미확인은 적격후보에서 보류, U-S=선호만 보존하고 가점/확정 금지, U-V=위주는 선호·필수원문이면 미확인 동의 전 충족추천 중단, U-C=동행으로 적합 단정 금지·아동명시 없으면 아동목적 차단, U-N/U-P=야경/사진 확인과 가점 금지·필수이면 충족불가 설명.

R-C: S/M/D 전역 아동 gate+검증태그 선호, A 직접 동행 우선+gate. R-M4: S/M/D 검증태그 선호(현재0), A 4개 필드만. R-M0: S/M/D 검증태그 선호(현재0), A 수동태그 구조화 미반영. R-T: S 명시종류 없을 때 태그 종류필터, M/D 슬롯만 적용, A 수동활동태그 미반영. R-E: S/M/D 태그 환경 필터 없음(코스UI 숨김), A 원문조건만. R-N: S 멋진야경만 임의 종류필터/야경은 무효, M/D 선호근거0, A 수동미반영. R-P: S 임의 종류필터, M/D/A 촬영조건 미반영.

### 화면 전체의 3층 구성안

| 층 | 사용자에게 묻는 것 | 권장 구성 | 기존 태그 처리 |

‘전통시장’, ‘독립서점’, ‘소품점’, ‘등산’, ‘트레킹’, ‘수영’, ‘맥주·호프’ 같은 구체 의도는 문장 또는 해당 활동의 상세 선택에서 받는다. 쇼핑이라는 넓은 버튼 하나로 이들을 대체하지 않는다. 한 단계에서 ‘볼링장 또는 보드게임’은 OR이고 ‘볼링 후 카페’는2단계다. 기존 활동을 줄인다는 이유로 사용자의 선택 가능한 실제 방문목적을 없애지 않는다.

유형별 적격후보가0개인 경우 해당 상세 종류를 삭제했다고 처리하기보다 ‘현재 자료에서 추천 가능한 후보 없음’을 표시한다. 특히 PC방/소품점은 빈 카테고리를 다른 시설로 채우지 않으며, 체험은 공방 분류의 존재와 프로그램 제공근거를 따로 보여준다.

| 소품 분류 | 0 | 0 | 이름만으로 소품점을 만들어내지 않음 |

‘쇼핑’을 시장/대형시설 네 단어에 고정한 현재 정책은 일반 쇼핑 뜻보다 좁다. 반대로 이를 모든 소매점으로 넓히면 상점 탐방과 일상 구매/B2B를 구분할 수 없다. **1차 코스 활동에서 내리고, 시장 구경 / 서점 구경 / 소품·기념품 구경을 상세 의도로 구분**하는 안을 권한다. 공개 태그를3개 즉시 추가한다는 뜻은 아니다. 실제 종류·소매 목적 데이터가 있는 항목부터 상세 선택을 열고, 소품/관광기념품 근거가 없으면 문장은 보존하되 후보 미확인을 설명한다.

현행 `_known_categories`에는 PC방/독립서점/문구/소품점 같은 상세값이 없으므로 DB에 서점이 존재하는 것과 현재 API가 그 의도를 정식 지원하는 것은 다르다. 상세 선택을 열기 전에 catalog·해석 허용값·정규화·필터·검증을 함께 추가해야 한다. 문자열을 ‘쇼핑’으로 덮어 지원된 것처럼 처리하지 않는다.

현재 기본 템플릿에 쇼핑이 자동 배치되는 것은 아니다. 따라서 ‘기본코스에서 쇼핑 삭제’의 실질적 변경은 **첫 슬롯 선택 목록에서 숨길지**의 제품 결정이다. 사용자가 직접 고른 기존 음식→쇼핑→카페를 자동으로 음식→체험→카페로 바꾸면 안 된다.

## 후보 부족·미확인 UX

2026-10-27 사용자 요청에 따라 [사용자 화면 문구 기준](ui-copy-policy.md)을 적용한다. 아래 근거·후보 수 구분은 검수 기록의 기준이며 개발용 경고를 화면에 노출하는 요구가 아니다.

- 단계별 `입력→신원/좌표→종류→목적→명시제외→아동gate→반경→필수조건→방문중복→AI전달` 분모와 제외사유를 반환한다. `eligible_total`과 AI에 보낸 표본수 `presented_count`를 구분한다. 현행 자연어 `candidate_counts`는 최대30개를 분할한 후라 전체 후보수로 읽으면 안 된다.
- 예: ‘쇼핑 단계: 설정한4.5km 안에 현재 분류와 조건이 맞는 후보0개. 식사354개·카페118개.’ 선택지는 **쇼핑 단계를 직접 바꾸기 / 출발지 또는 이동조건을 직접 바꾸기 / 이 요청 취소**다. 반경밖 예시는 거리와 ‘현재 조건 밖’ 표시 후 참고만 제공한다.
- 필수 실내/야외좌석 근거와 종류별 후보 수는 내부 메타데이터에서 구분한다. 사용자에게는 필요한 선택만 짧게 묻고, 후보 수·검증 통계·미확인 경고를 나열하지 않는다. 조건을 충족했다고 보장하지 않는다.
- soft 선호만 미확인이면 요청 종류를 유지하고 그 상태는 내부 기록한다. ‘조용함 미확인’ 같은 경고는 화면에서 생략한다. 근거가 없는 태그를 조용함·야경·사진 점수로 반영하지 않는다. 적격 후보가 요청수보다 적으면 실제 개수와 부족이유를 반환한다.
- 같은 방문을 다른 ID로 반복해 채우지 않는다. 별도 지점은 이름/주소/ID를 유지한다. 다른 코스 간 장소 공유 허용 등 기존 규칙은 보존한다.

## 활동 재구성과 코스 대안 다양성은 별도 문제

같은 신창역에서 친구와+힐링/여유+생일, 음식→자연·산책→카페 3대안을 고정 소스로도 재현했다. 종류 후보는354/8/118로 쇼핑 신고와 달리 빈 슬롯이 아니다. 결과가 바른찜갈비→신정호테마공원을 공통으로 쓰고 카페만 우즈/산시/그래비티로 달라져 사용자는 같은 코스로 느낄 수 있다. 태그를 늘리기만 해서 해결되는 문제가 아니다.

통합 담당자가 남긴 `local_artifacts/manual_qa/2026-10-25/sinchang_diversity_analysis.json`은 최종256옵션 중 첫 코스와 공유방문1개 이하인203옵션이 있음에도 현재 중복불이익0.08에서 같은 식당·공원이 선택됨을 기록한다. 이 수치는 해당 담당자의 추가 진단 자료이며 이 검토가 search 알고리즘을 수정한 것은 아니다. 별도 실기기 재현자료는 정확한 폰 요청이 캡처되지 않았다는 한계가 있다.

3개 대안을 요청하면 동일 슬롯 순서를 지키면서 주목적 활동·방문시설에 의미 있는 차이가 있는 대안을 기대할 수 있게 해야 한다. 단순 ID/상호 차이와 실제 다른 경험은 구분한다. 신정호 공원/정원처럼 같은 권역의 다른 이름만으로 다른 코스가 입증되지는 않는다. 부족할 때는 비슷한 대안임을 표시하거나 적은 수를 반환하되 조건을 넓히지 않는다. 코스간 다양성 정책과 `recommender/search.py` 수정은 통합 담당자의 소유로 남긴다. 생일·힐링 적합은 verified 태그0이므로 어느 코스도 충족했다고 주장할 수 없다.

## API·저장값 호환

1. UI 표시명과 안정된 내부키를 분리한다. 1차는 기존 문자열을 wire alias로 유지하고 정책 catalog에 canonical key/그룹/표시명/종류/중복·충돌 관계/상태를 둔다. 새로운 타입키를 도입할 경우 API 버전과 명시 migration을 먼저 정의한다.
2. `야경`/`멋진 야경`은 단일 선호로 정규화한다. `문화·역사 탐방`과 `박물관/전시`는 같은 1차 관람 그룹의 하위유형으로 정리하되 둘의 과거 요청을 임의로 같은 방문종류로 바꾸지 않는다. `소개팅/첫만남`과 `첫 데이트`는 동행/상황의 다른 차원이라 백엔드 의미를 강제 통합하지 않는다.
3. ‘가족과’는 아이 포함을 뜻하지 않는다. ‘유아·영아’와 ‘아이’는 서로 겹쳐도 편의 요구가 다르므로 내부값은 유지한다. 동아리/단체/회식은 간단한 화면에서는 ‘모임’ 아래 상세로 묶되 음식/음주를 자동선택하지 않는다. 감성/아늑함/로맨틱함 등 분위기는 중복 표시를 줄여도 원값을 보존하고 근거 없이는 무효 점수다.
4. 자동제안 태그와 직접 선택 태그의 출처·수정시점을 구분한다. 제안은 비어 있는 필드에만 적용하고 직접 선택을 clear하지 않는다. 구버전의 출처 없는 `persona_tags`는 기존 계약대로 처리하되 출처가 확인되었다고 새로 표시하지 않는다. 새 클라이언트는 catalog_version/직접설정 provenance를 선택필드로 전송하는 방안을 검토한다.
5. 저장된 여행·즐겨찾기의 원래 태그/slot_types/요청버전과 실제 장소 ID는 보존한다. 과거 쇼핑/관광지/등산 슬롯을 현재의 다른 활동으로 조용히 재작성하지 않는다. 재추천 시 이전 조건을 표시하고 수정된 해석을 확인한다. 현재 로컬 저장 DTO에 없는 원요청을 복구해낼 수 있다고 가정하지 않는다.
6. unknown 태그는 버전별로 지원불가/무시목록을 명시한다. 오래된 앱을 즉시400으로 깨뜨리는 allowlist 교체를 피하고, 새버전에서 그룹 충돌·unsupported 값을 일관되게 검증한다. slot_types의 기존8값과 3~5 최소수 계약, 자연어1~5단계 계약을 별도로 보존한다.

## 재실행과 산출물

`/opt/anaconda3/bin/python -B local_artifacts/tag_policy_review/reproduce.py`로 고정 소스와 read-only DB의 분류/API 모의재현을 다시 실행할 수 있다. `run_snapshot_tests.py`는 임시 소스/DB 복사본에서 관련 테스트만 실행한다. 둘 다 출력은 이 artifact 디렉터리만 쓴다.

- `snapshot_manifest.json`, `head_manifest.json`, `live_drift.json`: 파일별 SHA256·기준·변경중인 소스 범위. snapshot은 파일별 순차 복사이며 저장 중인 전체 트랜잭션 시점이라는 보장은 없음.
- `tag_inventory.json`: 전체47개·UI46개·그룹·현행매핑·각 태그 후보수·기본슬롯.
- `policy_matrix.json`: 태그별 정의/표시명/hard-soft/허용/제외/근거/미확인/충돌/4경로/양음성.
- `filter_reproductions.json`, `api_reproductions.json`, `child_name_audit.json`: 실제 ID·분류·분모·실패응답과 모의 AI 입력.
- `summary.json`, `snapshot_tests.json`, `snapshot_tests.log`: DB 전후해시·직접검사 결과.

실제 영업·소음·야외좌석·관람가능·연령허용·촬영·야경·산행경로는 이번 자료만으로 확인하지 못했다. 기존 검증 태그를 복원하거나 외부API/키/수집을 사용하지 않았다. 이 설계가 폰 화면에 적용되었다거나 새 분류가 완성됐다고 주장하지 않는다.
