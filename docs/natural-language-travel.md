# 원문 기반 여행 추천 계약과 실행

## 바뀐 흐름

기존 수동 추천 API는 유지한다. 새 앱은 문장이 있을 때 `intent_version: 1` 경로를 사용한다.

1. 원문과 확정한 위치·교통·개수·수동 선택을 `/travel/interpret`로 전송한다.
2. 서버가 AI 해석과 순서·제외·필수 조건·선호를 검증한다. 일반 해석 확인창은 생략하고 활동 선택·추천 방식 전환 등 필요한 선택만 묻는다.
3. 확인한 해석을 서명한 `intent_token`으로 추천한다. 재해석하지 않는다.
4. DB의 지역·좌표 품질·반경·장소 종류·제외·가족 동반 정책으로 후보를 먼저 제한한다.
5. AI가 제한된 실제 후보에서 비교·선택한다. 서버가 ID·순서·수량·동일 방문·근거를 재검증한다.
6. 결과에는 장소와 필요한 행동만 표시한다. 미확인 조건·규칙 대체·정렬 방식은 내부 데이터와 QA 기록에 보존한다. 화면 문구는 [사용자 화면 문구 기준](ui-copy-policy.md)을 따른다.

태그는 원문을 대체하지 않는다. 코스 API에도 `user_text`를 보낸다. 동행·분위기 태그를 직접 선택하면 그 선택이 우선하며 선택 항목에 반영한다. 실내·야외 위주는 미확인 선호로 기록한다. 기념일·생일 등 식사 목적은 아래 종류별 순위 정책에 반영하고, 감성 등 반영하지 못한 태그는 `unapplied_manual_tags`와 `manual_overrides`로 내부 기록한다. 활동 태그는 자연어 단계의 순서를 덮어쓰지 않는다. 기존 수동 입력·기존 저장 DTO·장소 ID·지도 연결 계약은 보존한다.

### 2026-10-28 요청 맥락의 순위 보존

`recommendation_context.py`의 `request_context`는 원문의 긍정 표현·수동 동행/분위기 우선순위·기념일 등 목적·명시 음식 종류를 보존한다. 전체 원문과 정확한 GPS를 후보 비교에 새로 보내지 않는다. compact AI에는 이 구조화한 맥락과 서버 검증 추천안만 전달하며 모델 호출 수와 출력 512토큰 제한을 유지한다.

기념일·생일·첫 데이트·프로포즈 또는 직접 표현한 로맨틱 식사의 일반 식당 검색은 분식·패스트푸드·간단한 식사 분류의 비용을 1.0 높인다. 후보를 제외하거나 프랜차이즈 여부를 추측하지 않는다. 명시 음식과 간단/빠른/저렴한 식사 요청이 기본값보다 우선하며 코스의 예외는 해당 방문에 한정한다. 스팟 비용, 무작위 변화/최근 추천 회피, 코스 검색/재계산/품질 검증에 같은 비용을 쓴다. 이는 학습된 정확도나 실제 가격·분위기 점수가 아니다. 스팟은 방문 경로로 다시 정렬하지 않는다.

기념일 부정, 기념관/기념품, 단순 날짜·기간은 기념일 근거가 아니다. 식당/밥집만 요청해도 유효한 넓은 종류이므로 구체 요리 선택을 강제하지 않는다. 가격·알레르기·영업 등 미해결 요구는 유지한다. 상세 최종 검증과 남은 데이터 한계는 [QA 후속 기록](feedback-overhaul-2026-10-28.md)에 보존한다.

아래 새 동작은 고정 모의 모델과 실제 읽기 전용 DB/서버 통합, 또는 회귀용 장소 표본으로 검사했다. 실제 상용 모델의 한국어 해석 정확도를 실측한 표는 아니다.

## 요청 및 해석 형식

기존 `/recommend/spot`, `/recommend/course` 필드는 그대로 사용할 수 있다. `intent_version` 생략 시 기존 경로다. 새 필드:

| 필드 | 계약 |
|---|---|
| `intent_version` | 정수 `1`만 지원 |
| `user_text` | 1,000자 이내. 코스에서도 사용 |
| `plan_mode` | `natural` 또는 `manual`. 자연어 단계는 1~5곳, 수동 코스는 기존 3~5곳 |
| `intent_token` | 해석 확인 후 추천에 전달. 30분 유효. 공유 서명키 미설정 시 프로세스 재시작 후 재확인 필요 |
| `accept_unverified` | 기본 false. 미확인 필수 조건을 가진 대안을 보기 위한 명시적 선택. 서명한 해석 필요 |

`/travel/interpret`에는 같은 입력과 `mode: spot|course`를 보낸다. 자연어 코스에서 `slot_types`는 비워야 한다. 수동 슬롯이 있으면 `plan_mode: manual`을 명시한다. 자연어 단계 수는 해석 결과로 정하고, 기존 `spot_count` 기본값 3으로 장소를 추가하지 않는다.

해석 결과 `travel_request`는 다음 내용을 갖는다.

- `schema_version`, `source_text`, `companion`과 원문 `quote`.
- 순서대로 연속된 `s1`~`s5` 단계. 각 단계의 활동·허용 종류·원문 인용·조건·선호.
- 조건의 `id`, `field`, `value`, `required`, `quote`. 지원 필드는 실내·야외·야외 좌석·현재 영업·접근성. 조건은 현재 모두 현장 미확인이다.
- 선호의 `id`, `field`, `quote`. 조용함·활기참·로맨틱함·시원함·여유로움은 확인된 사실로 사용하지 않는다.
- 종류별 `exclusions`, `ambiguities`, `unsupported`, 명시 방문 수와 근거.
- 선택적인 `requested_result_count`는 추천 개수이며 `requested_visit_count`와 구분한다. “카페 두 곳 추천”을 두 방문 코스로 만들지 않는다. 확정한 결과 개수가 원문과 다르면 수동 선택을 우선하고 적용 내역을 내부 기록한다.
- 서버가 적용한 `applied_controls`, `manual_overrides`, 사람이 읽는 `summary`.

해석의 미지원 종류·잘못된 인용·순서·모순·NaN 수량·누락한 직접 제외를 거절한다. 명백한 장소 종류와 야장 조건이 사라진 해석을 막는 보조 검사가 있다. 한국어 전체 의미를 코드의 단어 검사로 대신하지는 않는다. 모호하거나 지원 불가인 조건은 화면에서 문장 수정을 요구하며 검색하지 않는다.

`실내 카페`, `야외 공원`, `야외 좌석이 있는 카페`, `지금 영업 중인 카페`, `휠체어 접근이 가능한 카페`처럼 알려진 종류를 바로 수식하는 명확한 긍정 조건은 해당 방문의 필수 조건으로 보존됐는지 독립 검사한다. 누락·값 반전·선호로 약화·다른 방문으로 이동한 해석은 `intent_conflict`로 거절하며 모델을 재호출하지 않는다. `가능하면/가급적/되도록` 선호, 부정·한정·이중부정, 실내 놀거리/놀이터 같은 종류, 랜드마크 수식과 알려지지 않은 구문은 이 좁은 검사로 임의 해석하지 않는다. 이 검사는 현장 실내·영업·접근성의 사실 증거를 추가하지 않으며, 정상 필수 조건도 기존 미확인 대안 동의가 필요하다.

알려진 종류 사이의 `또는/혹은/나/이나`는 인접한 대안 묶음으로 다룬다. 각 대안에 직접 붙은 필수 조건의 교집합만 해당 방문의 공통 필수 조건으로 검증한다. `반드시 실내 카페 또는 반드시 실내 박물관`은 실내 필수 조건을 유지해야 하지만, `실내 카페 또는 공원`에서 공원에 실내 조건을 새로 만들지 않는다. 다른 방문의 대안 표현이 앞 방문의 검사를 생략시키지 않는다. 선호/허용은 앞의 `가능하면`뿐 아니라 뒤의 `선호해요/면 좋겠어요/도 괜찮아요`도 구분한다.

활동 종류를 추가 선택할 때 `실내에서 친구와 놀고 싶어`, `실내에서 하루를 보내고 싶어` 같은 명확한 위치 요청은 중간 동행·부사·목적 구절 때문에 사라져서는 안 된다. 정상 필수 조건은 해당 선택에 보존하고, 명시적 선호·부정·맥락 대안은 임의의 현장 사실이나 공통 필수 조건으로 바꾸지 않는다. 인용 구절의 방문 귀속은 앞 인용의 끝 이후에서 찾으며, 짧은 다음 인용이 앞 인용의 부분 문자열에 잘못 연결되지 않게 한다. 명시적 반복 방문은 검증된 동일 구절을 공유할 수 있다.

구조화된 아이 동반에 대한 원문 보조 검사는 아이 동행 동작에 붙은 `하지 말고/데려가지 말고/가는 대신/하기 싫다` 같은 직접 부정을 확인한다. 다른 장소에 붙은 `카페 말고`는 아이 미동반 근거가 아니다. 이중부정은 구분하고 동행 직접 선택 우선순위와 구형 요청의 보수적 처리를 유지한다.

이 조건 보존 정책의 버전은 `20261102-v11`이다. 공유키가 배포 뒤에도 같더라도 이전 `20261029-v10` 정책의 추천·활동 선택 토큰은 재확인을 요구한다. 이전 정책에서 누락된 필수 조건을 승인했던 토큰으로 새 검사를 건너뛰지 않게 하기 위한 갱신이며, 서명키 구성·함수·TTL을 변경하지 않는다.

알려진 장소 종류가 인접한 `와/과/및` 열거이며 끝에 `중 하나(만)`, `중에서 한 곳`, `가운데 하나`처럼 한 곳을 고르는 범위가 명시되면 같은 방문의 OR로 묶는다. 명시된 `둘/셋`의 열거 크기도 알려진 종류 수와 맞아야 한다. 선택 수량이 없는 `둘 다`, `하나씩`이나 `갔다가/다음`의 순차 방문은 이 규칙으로 OR로 바꾸지 않는다. 한쪽에만 붙은 실내 수식어를 공통 필수로 만들지 않지만, 모든 대안에 직접 붙은 공통 필수 조건은 계속 검증한다. 방문 수·추천 개수·인용 순서·수동 재배치 계약은 변경하지 않는다.

가족 후보 정책은 `유아는 아니고 초등학생 아이와 함께`처럼 연령 하위 유형을 부정하면서 별도의 긍정 동행을 명시한 경우를 구분한다. 정상 구조화 동행이 `아이와 함께`이고 원문에 알려진 학교 연령의 아이/자녀 또는 `다른 아이`와의 명확한 동행 근거가 함께 있을 때만 하위 유형의 속성 부정을 분리한다. 일반 `아이 없이`와 직접 동반 금지, 불명확하거나 모순된 동행은 전체 허용으로 넓히지 않는다. 이는 연령 적합성·시설 이용 가능성을 검증하거나 연령별 추천을 제공하는 기능이 아니다.

`아이 동반하지 말라는 건 아니고 아이와 함께` 같은 인용 금지의 부정은, 같은 동작 구절의 뜻을 명확히 부정하고 바로 이어지는 긍정 동행 근거가 구조화 동행과 일치할 때 구분한다. 뒤의 아무 긍정 단어나 원문의 아무 `아니`로 실제 금지를 무효화하지 않는다. 실제 `하지 말고/데려가지 말고/가는 대신`과 금지를 긍정하는 `말라는 뜻이고`는 계속 차단한다. 이 보완은 기존 v11에서 잘못 제외하던 정상 범위를 바로잡으며 서명키·토큰 정책 버전은 유지한다.


확정한 위치·교통·결과 개수는 모델이 바꿀 수 없다. 수동 동행·분위기 선택은 선택 항목에 반영하고 적용 내역은 내부 기록한다. 수동 슬롯을 바꿨을 때 원문의 필수 조건을 잃는다면 문장/코스 구성의 수정을 요구한다.

스팟에서 여러 단계가 나오면 `mode_switch_required: true`, `target_mode: course`, `target_count: 1`을 반환한다. 이때 토큰은 해당 코스 요청에 바인딩된다. 화면에서 **코스로 전환해 추천**을 누르기 전에는 코스를 요청하지 않는다. 코스 1개로 바뀐다는 문구를 표시한다. 단일 카페는 스팟을 유지한다.

### Python worker의 서명키 설정

독립적으로 초기화되는 Python worker를 여러 개 쓰면 서버 환경 또는 루트 `.env`의 `TRAVEL_INTENT_SIGNING_KEY`를 모두 동일하게 설정한다. 값은 정확히 64자리 16진수(32바이트)인 서버 전용 비밀값이며 앱·Node·저장소에 전달하지 않는다. 이 문서/예제에는 실제 키가 없다. 설정은 app의 dotenv 로드 이후 검증하고 토큰 사용 시 읽으므로, travel_intent를 먼저 import해도 설정이 무시되지 않는다. 잘못된 형식은 값을 노출하지 않는 설정 오류로 실패한다.

미설정 또는 빈 값이면 기존 프로세스별 임시 키를 사용하므로 단일 프로세스 개발 실행은 유지된다. 모듈을 미리 import한 뒤 fork한 worker는 같은 임시 키를 상속할 수 있지만, 독립 worker 간 공유나 재시작 뒤 유효성을 보장하지 않는다. 키 변경/제거 시 기존 추천·활동 선택 토큰은 거절된다. 공유키를 써도 30분 TTL, 요청 fingerprint, data_version, purpose 검사는 그대로 적용된다. 기존 실행 서버를 이 변경만으로 자동 재시작하지 않는다.

## 후보와 근거

실제 DB는 항상 읽기 전용이다. 신원 보류·좌표 품질·확정 지역·교통 반경·종류·제외·아이 활동 정책을 먼저 적용한다. 후보는 **전체 단계 합계 최대 30개**다. 단계별 예산을 나누고 종류별·가까운 순·인기도 순 목록을 번갈아 뽑는다. 인기도 상위 일부만으로 자르지 않는다. 현재 구현은 Kakao 후보 확장 검색을 호출하지 않는다.

아이 목적 장소는 `family_policy`에서 먼저 제한한다. 아이와 함께/유아 동반의 확정 선택 또는 명시적 키즈카페/실내놀이터 요청을 근거로 허용한다. 친구·연인·일반 가족 나들이·실내 위주·카페 투어는 허용 근거가 아니다. 수동 동행은 원문 동행보다 우선하고, 명시적 키즈 활동은 동행과 별도로 판단한다. 구형 경로에서 부정 범위가 모호하면 보수적으로 차단한다. 새 경로의 이중부정은 검증한 해석과 원문의 키즈 활동 표현을 함께 요구한다. 이 게이트는 일반 카페를 키즈카페로 바꾸지 않는다. 원본 분류와 ID도 바꾸지 않는다.

모델에게는 이름·분류·직선거리·근거 ID·미확인 조건만 전달한다. 해석에는 원문과 선택 지역만 보내며, 후보 비교에는 원문 전체·정확한 사용자 GPS·주소·환경 파일·로그를 보내지 않는다. 사용자가 원문에 직접 적은 개인정보까지 자동으로 제거하는 기능은 없다.

각 근거는 `source`, `snapshot`, `field`, `value`, `checked_at`을 갖는다. 현재 DB 분류와 좌표 계산의 현장 확인 시각은 없으므로 `checked_at: null`이다. 야외 좌석·영업·소음·분위기를 이름/카테고리로 입증하지 않는다. 확인 가능한 자료 필드와 `unverified_condition_ids`를 별도로 보낸다. 검증된 블로그 태그 0건 상태도 내부 데이터와 QA 기록에 유지한다. 사용자 화면에는 이 경고를 표시하지 않으며, 태그 부재와 원문 해석/후보 비교의 역할을 검수에서 구분한다.

필수 조건 근거가 없으면 `422 unverified_conditions`다. 이 응답은 추천 성공이 아니다. 필요한 선택은 짧은 행동 안내로 받고 개발용 미확인 경고와 단계별 후보 통계는 노출하지 않는다. 동의한 재요청의 `intent_status: unverified_alternative`는 내부 메타데이터에 보존한다. 후보 0건/부족은 종류·지역·반경을 자동 완화하지 않는다.

## 모델 결정 검증과 시간/비용 상한

모델은 제공한 ID 안에서 단계별 선택과 순위만 정한다. 자유로운 운영 사실/주소/이유를 반환하지 못한다. 짧은 이유는 `category_match`, `distance`와 실제 근거 ID를 서버가 문장으로 표현한다. 반환 조건 목록은 서버가 계산한 만족/미확인 목록과 정확히 같아야 한다.

후보 밖 ID, 같은 방문 중복, 단계 누락/재배열, 수량 오류, 잘못된 근거·이유·확인 주장, 중복 코스, 지역·반경·제외·장소 종류 위반을 거절한다. 한 코스 안의 동일 방문 판단과 뚜쥬루 브랜드 다양성은 별도다. 다른 코스 사이 일부 장소 공유는 허용한다. 브랜드 다양성은 확인된 4개 원본명에만 적용하고 부족 보충 통계를 유지한다.

| 항목 | 상한 |
|---|---|
| 해석 | 1회, 호출 대기 7초, 출력 2,300토큰 |
| 후보 비교 | 필요할 때 1회, 호출 대기 9초, 출력 5,500토큰 |
| 재시도 | 새 경로 0회. SDK 자동 재시도도 0회 |
| 외부 검색 | 0회 |
| DB 조회 | 추천 요청당 1회. 필수 조건 동의 전후 최대 2회 |
| 모델 입력/출력 | 호출별 UTF-8 36,000/24,000바이트 |
| 모델 실행 동시성 | 프로세스당 최대 4개. 늦은 호출은 종료될 때까지 슬롯 점유 |
| 추천 처리 | 22초 경과 검사. DB/CPU 단계에는 협력적 검사, 외부 모델 대기는 하드 제한 |
| 전송 제한 | 본문 16KB, Node 30초, Flutter 35초 유지 |

해석 실패는 `503 intent_unavailable`이며 AI 해석 성공으로 가장하지 않는다. 후보 비교 오류/시간 초과/검증 실패 시 추가 모델 호출 없이 수동 코스와 같은 제한된 후보 탐색·다양성·품질창 정책을 사용한다. 새 요청의 seed는 바뀌고 같은 요청 재확인은 seed를 유지한다. `selection_method: rules_fallback`을 내부 메타데이터와 저장 데이터에 보존하되 화면에서는 설명하지 않는다. 복합 의도를 만족한 AI 추천으로 표시하지 않는다. 필수 조건 미확인 상태는 대체 방식과 독립적으로 유지한다.

연타는 화면에서 잠근다. 뒤로 가기·화면 종료·시간 초과는 HTTP 요청을 중단하고 요청 버전을 폐기한다. Node도 클라이언트 연결 종료 시 Flask 요청을 중단한다. 이미 시작한 Flask/SDK 작업 자체를 강제 종료하지는 않으며 늦은 결과를 화면/저장 데이터에 적용하지 않는다.

응답 캐시는 없다. 재현 키는 원문·확정 설정·슬롯·태그·seed·해석·실제 후보와 근거·정책/데이터 버전을 포함한다. 고정 계획/모의 모델에서 동일 결과를 검사한다. 실제 모델의 생성 결정성은 보장하지 않는다. 토큰 서명 키는 프로세스 메모리에만 있어 현재 단일 프로세스 실행에 맞는다. 여러 WSGI worker로 운영하려면 공유 서명/토큰 저장 방식을 추가해야 한다.

## 오류와 저장 호환성

`intent_conflict`, `course_confirmation_required`, `unverified_conditions`는 422, 해석 서비스 실패는 503, 해석 토큰 변경/만료는 400 `intent_expired`다.
