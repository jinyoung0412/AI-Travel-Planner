# 장소 분류와 블로그 태그 근거 점검

2026-10-26 현재 소스 기준. 실제 수집·DB 재구축·태그 적용은 수행하지 않았다.

## 글의 장소 확인과 태그 귀속을 분리

한 글에 두 장소의 이름과 주소가 모두 있으면 두 장소 모두 언급된 글일 수 있다. 그러나 글 전체 해시태그가 두 장소 모두의 분위기나 동행 적합성을 증명하지는 않는다. 이전 자동 수집은 이 둘을 구분하지 않고 `gsTagName` 전체를 verified 태그로 만들었다.

이제 자동 수집은 이름·주소 확인 결과와 원문 태그를 감사 기록에 그대로 보존하고 `needs_review`로 둔다. 추천용 `blog_tags`와 `verified_posts`에는 게시물 전체 태그를 자동 게시하지 않는다. 재개 시 이미 가져온 글을 다시 호출하지 않는다.

기존 5장소 pilot의 수동 검토에서 해당 장소에 관한 취향 태그를 확인한 후 `export-reviewed`를 실행하면 `tag_review`가 생성된다. 승인한 태그 집합, 현재 장소의 이름·주소 identity, 원문의 canonical post key가 함께 저장된다. 다른 장소나 URL로 복사하거나 승인한 태그를 바꾸면 근거로 인정되지 않는다. 이 필드는 검토 과정의 출처 기록이며 현장 사실에 대한 암호학적 보증은 아니다. 기존 수동 신원 확인과 취향 태그 제외 규칙도 유지한다.

구형 `verified` 플래그와 이름·주소만 있는 proof는 새 재구축/런타임 검증에서 태그 근거로 통과하지 않는다. 재구축에서는 원본 증거를 격리 기록에 남긴다. 실제 현재 DB는 검증 태그 0건이므로 이번 변경으로 실제 검증된 추천 근거가 삭제되는 것은 아니다. 기존 격리 이력을 복원하지 않는다.

## 검색어는 실제 분류가 아님

공원 검색에서 상세 분류를 읽지 못한 카페가 `공원`으로 저장되면 추천 목적이 잘못된다. 새 수집은 실제 분류가 없으면 빈 분류를 유지하고 검색어는 `search_category`에 보존한다. 전처리는 명시된 `search_fallback` 분류를 사실로 사용하지 않는다.

병합 시 분류와 `category_source`를 같은 장소 identity의 한 원본 행에서 함께 선택한다. 공급자 분류가 검색어 대체값에 덮이거나, 공급자 분류에 fallback 출처가 잘못 붙지 않는다. 과거 출처가 없는 분류는 `legacy_unknown`으로 남기며 일괄 삭제하지 않는다. 장소 행과 수집 출처는 보존한다.

## 이전 상태 보존

ID 이전은 기존 `fetch_error`, `interrupted`, `parse_unavailable`, `needs_review`, `no_verified_posts` 같은 상태를 `legacy_unverified`로 일괄 덮지 않는다. 상태가 비어 있는 실제 과거 행에만 legacy/동명 상태를 부여한다. 태그 근거 재검증·백업·격리·장소 ID 보존은 그대로 적용한다.

## 검증과 한계

모음글의 태그 교차 전파 차단, 수동 승인 후 장소별 분리, 다른 글/태그로의 승인 복사 차단, 미검토 원문 감사 보존과 재개, 분류 출처 원자성, 이전 상태 보존을 합성 데이터와 임시 DB로 검사했다. 실제 네이버 DOM·원문 내용·취향 정확도는 이번 검사로 확인되지 않았다. 수집 제외 목록의 이름 부분문자열 오탐과 행정구역 수집 범위는 별도 정책 검토가 남아 있다.
