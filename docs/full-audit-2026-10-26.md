## 수정한 결함과 동작

### 추천 조건

- `음식점 또는 카페`에서 음식점 범위가 사라지던 정규화를 수정했다. 구체적인 음식 종류 수식은 보존한다.
- `음식점 또는 조용한 카페`처럼 수식어가 끼는 선택도 보존하고, 단계별 종류 정규화에는 해당 단계의 원문 인용만 사용한다. `근처`나 무관한 부정 표현이 있다는 이유로 종류 검사를 전부 생략하지 않는다. `천안역 근처 닭갈비`를 한식 전체로 넓히는 모델 결과는 거절한다.
- 실내·야외 위주 태그는 미확인 선호로 기록한다. 생일·감성처럼 근거 또는 적용 규칙이 없는 태그는 `unapplied_manual_tags`와 `manual_overrides`로 안내한다.
- 수동 실내 선호와 원문의 필수 야외 조건 등이 충돌하면 수정을 요청한다. 부정 조건을 `실내 아님`으로 표시한다.
- 검색어를 상세 카테고리 대신 넣었다고 명시된 `search_fallback` 분류는 사실 근거로 통과시키지 않는다. 출처가 없는 과거 자료는 일괄 삭제하지 않는다.
- 자연어 추천은 실제 분류가 비어 있는 검색어 전용 후보를 제외한다. 분류 출처가 없는 과거 자료는 `legacy_unknown`으로 표시하고 설명은 등록된 분류를 기준으로 한 것임을 명시한다.
- 스팟에도 출발점 직선거리와 기존 점수의 품질 기준을 추가했다. AI 선정 비용을 규칙 결과와 비교해 순위별 비용이 0.15를 넘게 나빠지면 규칙 결과로 대체한다. `randomize=true`에서는 최대 0.04의 seed 변화를 주어 비슷한 후보의 선택을 바꾸며, 품질 차이가 큰 후보를 무작위로 앞세우지 않는다. 실제 취향 만족도의 학습 점수는 아니다.
- 직접 구성한 슬롯이 문장에 나온 구체 종류를 더 넓은 활동으로 대체하면 변경 내용을 확인 안내에 표시한다.

### 앱 경험

- 전체 코스의 방문 순서·거리·현재 코스와 다른 장소 수를 비교하고 선택한 코스로 이동할 수 있다.
- 조건 수정과 같은 조건 새 추천을 분리했다. 새 추천은 새 seed를 사용하고 해석/미확인 조건 동의를 재사용하지 않는다.
- 실패하거나 확인을 취소해도 마지막 성공 결과와 원래 입력을 유지하며 `이전 추천 다시 보기`로 돌아갈 수 있다.
- 해석 확인의 문장 수정 버튼이 실제 문장 단계로 이동한다. 취향 미확인 요약은 접힌 상세 내용 밖에서도 보인다.
- 새 결과가 이전과 같은 구성일 때 안내하며, 다른 후보가 없다고 단정하지 않는다. 스팟 번호가 방문 순서인지 추천 순서인지 표시한다.
- AI 태그 자동 선택이 기존 수동 선택을 바꾸면 동행 변경 전후와 추가·해제 내용을 확인한다. 취소하면 기존 선택을 유지한다.
- 390×844 합성 예시를 실제 Flutter 위젯으로 렌더했다. 작은 320px 화면과 1.8배 글자에서도 코스 비교를 검사했다. 이미지는 실제 추천이나 휴대폰 설치 증거가 아니다.

### 근거·수집·이전

- 한 글이 장소를 언급한다는 증거와 그 글의 태그가 해당 장소를 설명한다는 증거를 분리했다. 자동 수집은 원문을 감사 기록에 남기고 `needs_review`로 보존한다.
- 수동 승인 태그를 현재 장소 identity·원문 canonical key·승인 부분집합에 묶는다. 다른 장소/게시물/태그로 옮긴 근거는 거절한다. 메모리 안에서 태그 목록을 변경해도 승인 목록이 함께 바뀌지 않도록 분리했다.
- 분류와 출처를 같은 원본 행에서 함께 병합한다. 실제 상세 분류가 검색어로 덮이지 않게 했다.
- ID 이전 시 실패·중단·검토 대기 상태를 일괄 덮어쓰지 않는다. 원본 근거와 격리 이력은 보존한다.
- 자세한 계약은 [데이터 근거 점검](data-evidence-review.md)에 있다.

### 서버 연결과 재현 검사

- 서버가 HTTP 오류를 반환한 경우를 연결 실패와 구분한다. 내부 오류 내용은 노출하지 않는다. 후보 부족처럼 사용자가 고칠 수 있는 정상 오류 계약은 유지한다.
- `scripts/evaluate_recommendations.py`를 추가했다. 외부 호출 없이 실제 DB를 읽어 지역·교통·활동별 카테고리/반경/신원/다양성/같은 seed 재현을 평가한다. 성공과 부족 사례를 함께 기록한다.

## Claude 지적의 채택 여부

실제 보고 모델은 `claude-opus-5-5`, 요청 effort는 `high`다. 공급자는 effort를 독립 보고하지 않으며 CLI 인수 적용으로 확인했다. 526초 실행 후 완료 보고를 받았고, 읽기 도구 이외 권한 거부와 고정 복사본 변경은 0건이다. 검토 중 실제 작업트리에서 개선이 진행됐으므로 보고서 줄 번호를 그대로 결함 위치로 채택하지 않고 최신 코드를 대조했다.

## 검증 범위

추천 평가: 신창역·온양온천역·천안역·두정역 × 차량/대중교통 × 산책/문화/실내놀거리/체험의 32개 조합, 각 3개 seed 및 첫 요청 재현을 검사했다. 각 조합은 3코스를 반환했고, 코스끼리 공유 방문은 최대 1곳, 서로 다른 seed의 결과 묶음은 각각 달랐다. 신창역 대중교통의 식사/산책/카페 후보는 354/8/118, 문화는 2곳, 실내 놀거리는 1곳이었다. 따라서 일부 활동 장소가 반복되는 것은 후보 부족의 영향도 있다.

스팟도 4개 출발점 × 2개 교통수단 × 카페/산책의 16개 조합을 검사했다. 64회 요청(각 3 seed + 첫 요청 재현)에서 종류·반경·중복 제한을 지켰고, 10개 조합에서 장소 구성이 달라졌다. 나머지 6개는 좋은 후보가 우선돼 같은 구성이 나왔다. 새 seed가 반드시 다른 결과를 보장하지 않으며 화면에서도 같은 구성임을 안내한다. 신창역 쇼핑 후보 0곳 및 문화 장소 2곳으로 3회 방문을 요구하는 두 음성 대조군은 조건을 넓히지 않고 422로 응답했다.

이는 카테고리·거리·중복·제약 구현 검사다. 만족도, 실제 모델 의미해석 정확도, 현장 분위기·생일 적합성·실제 영업·교통 접근성에 대한 정확도 수치가 아니다.

## 최종 완료 기록

- 이름 부분문자열 수집 제외 정책과 지역 수집 범위는 실제 누락 규모 검증이 남아 있다. 근거 없이 제외 목록을 제거하거나 대량 재수집하지 않았다.
- 휴대폰 USB 연결이 없어 실기기 설치/새 UI 조작 검증은 대기 중이다. 기존 휴대폰 데이터를 변경하지 않았다.
- 소스 변경은 integration 작업트리에 보존하며 원격 push·main 병합·원격 배포는 하지 않았다.
