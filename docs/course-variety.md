# 코스 대안의 구성 차이와 새 추천의 변화

코스 3개가 같은 식당·공원을 공유하고 카페만 바뀌는 문제를 줄인다. 장소 종류·지역·출발점 반경·명시 제외·같은 방문 중복 금지는 그대로 적용한다.

## 선정 기준 (2026-10-29 개정)

- 코스 간 정확 방문 중복 0을 거리·인기도 비용보다 먼저 만족시킨다. 요청 지역·출발점 반경·종류·제외 조건을 넓히지 않는다.
- 조건을 통과한 전체 후보를 코스 수×방문 단계에 동시에 배정한다. 전체 매칭으로 중복 없는 구성이 가능한지 확인하고, 뒤 코스의 유일한 후보를 앞 코스가 소비하지 않도록 남은 배정을 보존한다.
- 검토된 신정호 관광 권역도 가능한 경우 분리한다. 정확 장소 신원과 관광 권역은 별개이며, 신원 중복은 항상 금지한다. 같은 코스 안의 다른 시설 방문까지 권역만으로 금지하지 않는다.
- 중복 없는 구성이 불가능하면 최소 비용 흐름으로 전체 반복 방문 수, 반복의 집중도, 장소 품질 순으로 최적화한다. 식당·카페가 충분한데 공원 한 곳이 부족하다는 이유로 다른 종류까지 반복시키지 않는다.
- 동일 코스가 여러 번 나온 경우 방문 단계별 교환으로 반복 수를 유지하면서 서로 다른 코스로 복구한다. 계산 자원 한도나 복구 불가능 시 기존 탐색과 전체 후보의 반복 감소 대안을 비교하며, `minimum_reuse_certified=false`와 사유를 남긴다. 이 예외에서는 전역 최소값을 보장하지 않는다.
- `0.15` 비용창은 중복 방지보다 우선하지 않는다. `0.04` 무작위 폭과 최근 추천 회피는 중복 조건을 만족하는 비슷한 품질 후보에 적용한다. 완전 비중복으로 이동 거리가 늘 수 있고 표시 거리는 도로 경로가 아닌 직선거리 합계다.
- `course_diversity`에 반복 방문 수, 0중복 가능 여부, 최소화 방법·확인 여부를 기록한다. 검토 권역 정책이나 방문 중복 비교는 실제 매장 분위기·영업 상태의 증거가 아니다.

## 요청과 재현

앱은 새 `RecommendationRequest`를 만들 때 31비트 `seed`를 새로 만든다. 해석 확인, 스팟에서 코스로 전환, 미확인 대안 동의는 같은 값을 유지한다. `randomize: true`로 좋은 후보들 사이에서 변화를 요청한다. 같은 장소가 다시 나오는 것은 가능하다.

직접 API 호출에서 `randomize`를 생략하면 기본값은 false, `seed`는 기존처럼 0이다. 명시한 같은 값으로 수동 코스는 재현할 수 있다. 해석 토큰은 `seed`와 `randomize`에도 묶인다. 실제 생성형 모델의 완전한 결정성까지 보장하지 않는다.

자연어 코스도 전체 적격 후보에서 코스를 구성하고 이후 선택된 장소를 보존해 AI 비교 자료만 압축한다. AI는 완성된 코스의 순서를 비교한다. 전체 후보의 점수 정규화를 보존해 압축 후 품질 검사에서 같은 코스를 잘못 거절하지 않는다. 최종 지역·반경·종류·제외·방문 신원 검증은 유지한다. 스팟 목록은 이번 변경 대상이 아니다.

자료는 `local_artifacts/manual_qa/2026-10-25/sinchang_course_variety_after.json`이다. 원래 실행 서버의 응답과 휴대폰 화면은 별도로 보존했다. 새 코드의 실제 모델·휴대폰 동작, 현장 적합성·영업·대중교통 소요시간을 실측한 결과는 아니다.

## 2026-10-30 방문 순서 보존·왕복 동선 감소

사용자는 식사→산책→카페 순서를 유지하면서 3번 근처를 먼저 지나 다시 돌아오는 코스를 줄여 달라고 요청했다. 장소 좌표의 방향 반전과 이후 장소에 대한 앞 구간의 근접을 제한된 추가 비용으로 반영하고, 같은 활동 단계의 장소 교체·코스 간 교환으로 구성을 개선한다. 활동 순서·지역·반경·제외 조건·장소 중복 최소화·분위기 적합성 비용 한도를 유지한다. 추천 과정에 길찾기 API 호출은 추가하지 않았다.

무작위 추천에서는 작은 개선까지 모두 같은 최적 조합으로 수렴시키던 초기 보완안을 수정했다. 충분히 큰 동선 개선에만 교체를 적용하고 기존 seed·최근 추천 회피 정책을 유지한다. AI의 최종 코스 비교에서도 좌표 기준 우회 및 총거리의 과도한 악화를 차단한다. 응답 metadata.route_coherence는 이 평가가 실제 도로 최적화가 아님을 명시한다.

검증: Python 전체 1,236개 통과. 봉명역·천안역·온양온천역 × seed 11/29/47의 9개 조건·27개 코스를 읽기 전용 실제 DB로 비교했다. 식사→산책→카페 및 조건별 코스 간 공유 방문 0을 유지하고 각 출발점의 세 seed 결과가 서로 달랐다. 평균 직선거리 2.502→2.333km(약6.8% 감소), 좌표 삼각 우회량 0.860→0.472km(약45.1% 감소). 이 값은 도로 이동거리나 소요시간이 아니다.

별도 실제 대중교통 길찾기: 봉명역 seed11의 전후 3개 코스 모두 ready. 실제 제공 경로 기하의 합계 12.695→10.835km, 역방향 겹침 추정 1,058.4→879.6m(약16.9% 감소). 출발역→첫 장소 접근은 제외했고 5m 샘플·10m 이내 비교이므로 전 지역·전 조건의 성능 보장은 아니다.

남은 한계: 유성각→일봉근린공원→슈에뜨베이커리는 여전히 후보로 나올 수 있다. 직선 구간은 카페와 약863m 떨어져 있지만 실제 도로는 약132m까지 접근하므로 좌표 평가만으로 원래 문제를 완전히 배제할 수 없다. 해당 조합의 실제 왕복이 제거됐다고 보고하지 않는다. 도로 기반 최종 후보 재평가 및 공원의 대표점·입구 검토는 후속 과제다.
