# 2026-11-01 API 추가 호출 없는 QA

이 작업은 Claude API 실호출 중지 상태를 유지한 채 수행한다. 기존 실호출 254건 중 실패 60건을 분석했고, 6,916건 조합은 별도의 오프라인 검사로 기록한다. 기존 실호출 기록과 계획표의 실행 상태는 변경하지 않는다.

## 실패 60건 분석 및 수정

| 기존 실패 | 건수 | 확인된 문제 / 수정 |
|---|---:|---|
| 태그 제안 실패 | 19 | 기존에는 제안 실패가 503으로 전달됐다. 실패 시 추가 호출 없이 기존 원문 근거 규칙으로 태그를 제안한다. 분위기 외 그룹에서 여러 후보가 나오면 임의로 하나를 고르지 않는다. 반환 메타데이터에 규칙 복구임을 명시한다. |
| 종류 누락: 음식점이나 카페 | 10 | 검증기가 OR 대안 누락을 감지했다. 전체 문장이 제한된 단순 OR 문법과 일치할 때 두 대안을 보존한 계획으로 복구한다. |
| 종류 누락: 공원 바로 옆 카페 | 9 | 코드에서 `바로 옆`을 랜드마크 관계로 인식하지 못했다. `바로` 수식어를 허용해 공원을 별도 방문 대상으로 강제하지 않는다. 인접 거리 조건이 실제 충족됐다고 보장하는 기능은 추가하지 않았다. |
| 반복 방문 quote 순서 | 10 | 같은 `카페`라는 원문 하나로 두 방문을 표현해도 두 번째 원문 등장 위치를 요구했다. 명시된 두/세 곳의 순차 방문 수량과 종류가 일치할 때 같은 근거 구절을 재사용할 수 있도록 수정했다. 추천 대안 두 개 요청은 반복 방문으로 바꾸지 않는다. |
| 해석 스키마 오류 | 8 | 필수 키/배열 계약의 검증 실패. 프롬프트에 필수 키·빈 배열 규칙을 보강하고, 검증 실패는 조건 확인 안내(422)로 처리한다. 원본 응답이 없어 어느 키가 잘못됐는지는 확정하지 않았다. |
| 종류 없음 | 1 | 유효한 장소 종류가 없는 해석을 추천에 사용하지 않고 조건 확인을 안내한다. |
| 기타 해석 검증 실패 | 2 | 정확한 내부 원인은 저장되지 않았다. 검증 실패 시 안전하게 조건 확인을 안내하고, 서비스 연결/시간 초과는 별도 서비스 오류로 유지한다. |
| 라벨 오류 | 1 | 라벨·사유의 비어 있지 않은 80자 제한을 프롬프트에 명시하고, 검증 실패 시 조건 확인을 안내한다. |

공통적으로 검증 기준을 느슨하게 해 없는 장소·누락된 필수 조건을 통과시키지 않는다. 복구 문법은 문장 전체와 일치해야 하며 예산, 실시간 영업, 대기, 실내/야외, 위치 관계 등의 추가 표현이 붙으면 제한 문법으로 복구하지 않는다.

## 검사의 의미

- 과거 로그에는 Claude의 **원본 출력이 없다**. 60건 검사는 저장된 오류 유형을 대표하는 **오류 주입 검사**이며, 과거 원본 출력의 완전 재생 검사가 아니다.
- 6,916건의 기능 검사는 활동/명시 종류마다 지역별 최대 8개 실제 장소를 추출한 표본을 사용하며, 전체 DB 부하 검사는 아니다. 원래 조합의 출발지·지역·이동수단·추천 수·태그를 사용한다. 해석은 명시적인 시나리오 고정 응답으로 대체한다. AI 순위 선택에는 시간 초과를 주입해 실제 규칙 대체 추천을 검사한다.
- 각 행에서 요청 파싱, 선택 조건 적용, 확인 안내 또는 실제 DB 추천을 수행한다. DB ID 존재, 지역, 출발지 반경, 코스 내 중복, 방문 종류 및 결과 수 상한을 검사한다. 야장·영업중·예산·대기·인접 조건 및 모순·지역 밖·없는 장소 요청은 확인 안내가 나오는지 검사한다.
- 같은 카탈로그 입력에 대한 서비스 지역·신원 보류·좌표 품질 검사는 입력 DataFrame 전체 일치 확인 후 결과를 재사용한다. 요청별 동행 정책·반경·태그·점수·경로 선택은 실행한다.
- CPU 경쟁으로 고정 응답이 시간 초과되는 일을 방지하기 위해 조합 검사에서 고정 응답은 동기 실행한다. 실제 시간 제한·늦은 응답 처리는 별도의 회귀 테스트가 검사한다.
- Python 오프라인 경계를 앱 import 전에 설치한다. 환경의 자격 증명을 제거하고 `.env` 로딩과 소켓/HTTP 전송을 차단한다. Flask 테스트 클라이언트를 사용하므로 서버 포트나 외부 API가 필요 없다.
- 이 결과는 **실제 Claude의 문장 해석 정확도·프롬프트 개선 효과·추천 순위 품질**을 증명하지 않는다. 지도 SDK·휴대폰 터치·렌더링도 별도 검사 대상이다.

## 전체 DB 부하 확인은 별도 미해결 항목

전체 DB를 사용한 초기 병렬 검사 기록은 `full-db-preliminary/`에 보존했다. 이 단계의 추천 503은 기능 조합 검사 결과에 섞지 않는다. 초기 기록에는 추천 오류 본문이 없어 모두 처리 시간 초과라고 확정할 수 없다. 전체 DB를 사용한 별도 고정 응답 단일 검사에서는 천안의 3방문 코스 1개가 200으로 반환됐고 약 9.95초가 걸렸다. 실제 API 응답 시간은 포함하지 않은 값이다. 서버에는 22초 제한이 있으므로 병렬 부하와 합쳐진 지연 위험은 남아 있다. 운영 환경의 동시 사용자 부하 성능은 이번 표본 기능 검사로 보장하지 않는다.

## 회귀 테스트

기존 전체 Python 검사: 1,257 통과, 2 실패. 실패한 2건은 조건 확인 HTTP 상태 기대값 수정과 처리 시간 메타데이터를 내용 결정성 비교에서 제외하는 수정 후 재검사했다. 최종 관련 4개 테스트 파일의 269건은 모두 통과했다.
