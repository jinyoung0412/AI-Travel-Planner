# 시연 준비: 맥주·호프 코스와 동시 사용 — 2026-11-01

## 코스 구성 수정

코스 방문 활동에 `맥주·호프`를 추가했다. 기존 `식사`는 계속 음식점 종류만 사용하고, 기본 활동 태그 6개와 이전 6,916건 계획표는 변경하지 않았다. 코스 선택지는 7개가 되어 길이 3~5의 순서 경우의 수는 19,551개다. 과거 계획표가 이 새 전체 공간을 검증한 것으로 간주하지 않는다.

야장을 원하면 코스의 식사 방문을 `맥주·호프`로 바꿀 수 있다. `야장`은 야외 좌석 필수 조건으로 유지한다. 실제 야외 좌석 자료가 없어 확인 안내를 먼저 표시하고, 사용자가 미확인 대안 보기에 동의한 경우에만 해당 대안을 반환한다. 야외 좌석이 확인됐다고 표시하지 않는다.

## 동시 사용 개선

DB 읽기·신원 정리·서비스 지역·좌표 품질 같은 정적 처리를 최대 3개 스냅샷으로 제한해 재사용한다. 동시에 첫 요청이 들어와도 같은 키를 중복 로드하지 않는다. SQLite 본체와 WAL 변경·파일 교체를 감지해 무효화한다. 매 요청에 복사본을 제공하므로 출발점 반경·동행·취향·난수·코스 결과가 다른 사용자에게 섞이지 않는다. 보류된 특정 신원 확인도 전체 레코드를 사전으로 바꾸지 않고 처리한다.

전체 천안 DB, 동일 장비, 3방문 코스 1개, 서로 다른 난수, 고정 AI 응답에서 비교했다.

| 조건 | 수정 전 | 수정 후 |
|---|---|---|
| 단일 요청, 최초 로드 포함·프로파일링 실행 | 약 2.45초 | 약 2.38초 |
| 4명 동시 요청 | 약 6.85~7.03초, 모두 200 | 약 3.68~3.76초, 모두 200 |

추가로 실제 Claude API와 Node→Flask 경로를 사용한 4명 동시 요청은 전부 `ai_candidates`로 성공했다. 전체 해석+추천 시간은 약 6.65~6.76초였다. 이 결과는 이 장비의 4명 조건이며 대규모 부하 성능을 보장하지 않는다.

## 검증

- Python: 최종 전체 1,289건 통과.
- Node: 112건 통과.
- Flutter: 294건 통과, 정적 분석 이상 없음. 로컬 파일 동기화로 생긴 저장소 밖 ` 2.dart` 복제 파일은 정적 분석용 소스 복사본에서 제외했으며 원본은 삭제하지 않았다.
- Flask↔Node 게이트웨이 오프라인 검사: 16건 통과.
- 기존 실패 유형 오프라인 주입: 60건 통과.
- 실제 API: 4명 동시 추천 정상, 야장 확인 전 422/동의 후 200 및 야외 좌석 미확인 표시 확인.
- 폰: 최신 debug APK 업데이트 설치 완료. 최종 화면 확인 결과는 아래에 기록한다.

API 검사는 종전 약 $0.61을 포함한 동일 누적 지출 가드를 사용했다. 이번 요청의 총 $3 상한보다 여유 있게 $2.80에서 중지하도록 낮췄고, 다시 실행해도 지출 상한이 높아지지 않도록 했다. 누적 비용과 폰 결과는 작업 종료 시 확정한다.

## 재현

```sh
python scripts/benchmark_concurrency.py --label current --profile
python scripts/offline_failure_replay.py
python scripts/offline_qa_matrix.py --output local_artifacts/offline-matrix
```

위 명령은 API를 차단한다. `tests/fixtures/qa_matrix`의 압축 조합·정제한 실패 기록을 사용하므로 비공개 실호출 기록 없이 실행할 수 있다. 원래 실호출의 signed token·API 키·원문 응답은 Git에 넣지 않는다. API 실호출과 로컬 사진·APK는 별도 로컬 증거로 보관한다.
