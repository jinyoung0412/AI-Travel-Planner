# 남은 해석 검증 9건 후속 수정 — 2026-11-01

9개 원래 조건을 모두 재확인했고, 수정 후 각 조건을 두 번 반복한 **18/18건이 해석 검증을 통과**했다. 추가 비용은 약 **$0.104**, 직전 테스트부터의 누적 비용은 **$0.614225**다. 관련 오프라인 회귀 테스트 292건도 통과했다. 호출은 종료했다.

## 어떤 9건이었나

| 유형 | 원래 건수 | 예시·문제 |
|---|---:|---|
| 응답 구조 오류 `intent_schema` | 7 | “줄 안 서고 한적한 식당”. 추가 원문 진단에서 대기 상태 부정을 식당 종류 제외로 잘못 넣고, 제외 객체에 허용되지 않는 `reason` 키를 덧붙인 응답이 확인됐다. |
| 종류 없음 `intent_category_required` | 1 | “기념일에 야장 가고 싶어”. 검증 후 유효한 장소 종류가 남지 않았다. 원래 원문 응답은 저장되지 않아 빈 배열이었는지, 허용되지 않은 종류 표현이었는지는 확정할 수 없다. |
| 표시명 오류 `intent_label` | 1 | “부모님 모시고 식사하고 싶어”. 당시 검증은 활동명·사유가 문자열이 아니거나 비어 있거나 80자를 초과하면 거부했다. 원래 응답이 없어 정확한 하위 원인은 확정할 수 없다. |

원래 사례 ID는 QA-0073, QA-0125, QA-0151, QA-0177, QA-0203, QA-0227, QA-5013, QA-1783, QA-5429다. 천안역·두정역·천안아산역과 스팟/코스, 원래 태그·결과 수·방문 수·순서를 유지해 검사했다.

## 수정 내용

- 직전 작업의 대기·야장 예시 보강이 원래 9개 조건에서도 작동하는지 먼저 확인했다. 이 기준 재검사는 9/9 통과했다.
- 활동명·설명은 표시용 문자열이므로, 앞뒤 공백을 정리하고 80자를 넘으면 말줄임 처리한다. 문자열이 아니거나 공백뿐인 값, 비정상적으로 큰 값(2,048자 초과)은 계속 거부한다.
- 이 정리는 **원문 인용, 장소 종류, 조건, 수량에는 적용하지 않는다.** 긴 설명으로 표시가 짧아져도 대기 정보 미확인과 야외 좌석 필수 조건은 원래 구조에 남는다. 없는 종류·가짜 근거·잘못된 조건 타입은 여전히 차단한다.
- 부모님 동행만으로 휠체어·고령·조용함·고급·한식 같은 추가 조건을 추정하지 않도록 규칙을 보강했다. 짧은 `식사` 활동명과 넓은 음식점 종류로 표현하는 JSON 예시를 추가했다.

## 수정 후 실제 확인

- 9개 조건 × 2회 = **18건 모두 문장 해석 검증 통과**.
- 원래 설정을 포함한 `/travel/interpret` 응답은 **200 16건 / 의도된 코스 충돌 안내 422 2건**이다. AI 해석 검증 오류 코드는 다시 발생하지 않았다.
- 부모님 식사는 두 번 모두 동행 `부모님 모시고`, 활동 `식사`, 종류 `음식점`, 추가 시설 조건 없음으로 해석됐다.
- 대기 요청은 식당 제외가 아니라 실시간 대기 미확인 조건으로 유지됐고, 야장은 `outdoor_seating=true, required=true` 조건으로 유지됐다.

### 야장 사례에 남은 별도 코스 제약

QA-0227은 직접 구성 순서가 `식사 → 산책·자연 → 카페·디저트 → 전시·문화관람`이다. 현재 직접 구성의 식사 슬롯은 맥주·호프 종류를 포함하지 않아 이 대안을 배치할 수 없다. 따라서 두 번 모두 조건 수정 안내가 나왔다. **해석 검증 문제는 해소됐지만 이 직접 구성에서 야장 추천이 완료된 것은 아니다.** 코스 종류 호환 범위나 구성 UI를 넓히는 변경은 이번 수정에 포함하지 않았다. 야외 좌석 확인 자료가 없다는 제한도 그대로다.
