## 실제로 확인한 흐름

- 신창역·아산·대중교통·친구와·힐링/여유·생일, 식사→산책·자연→카페·디저트의 3개 코스.
- 비교 창의 세 코스, 스크롤, 세 번째 코스로 이동, 코스 저장 대상과 순서 일치.
- 같은 조건으로 재추천 시 식당/카페 구성 변경. 매번 전부 새로운 결과를 보장하지 않는다.
- 조건 수정, 단계별 뒤로 이동, 실패 전 추천 복원.
- 문화×3 후보 부족 안내, 조건 수정 복귀. 조건을 자동 변경하지 않음.
- 지도 참고 위치 확인창→실제 카카오 웹지도→앱 복귀. 확정 장소 상세 연결과 구분됨.
- 저장 코스 상세, 앱 강제 종료 후 재실행 시 보존, 삭제 취소, QA 항목만 삭제.
- 천안·자동차·카페·디저트 스팟 3곳, 다시 추천 시 구성 변경.
- AI 태그 교체 전 변경 확인 및 취소 시 기존 선택 유지.
- 한글 문장 해석 및 미확인 조건 안내는 아래 최종 증거와 결과 파일을 따른다.

## 자동 검사와 실호출 구분

- 최종 Python 전체 934개 통과. DB/임시 재구축 보존 검사 통과.
- 최종 Flutter 전체 178개 통과, analyze 이상 없음.
- 추천 행렬: 코스 32개 시나리오의 seed 변화와 재현성, 부족 조건 2개, 스팟 16개 시나리오를 검사했다. 스팟 변화는 10/16이며 나머지는 같은 결과가 허용된다.
- 실제 한국어 API 요청 `친구와 조용한 카페에 가고 싶어요`: 최초 후보 선택 `provider_timeout`(4.323초), 대기 조정 후 `invalid_selection`(6.54초), 형식 계약 개선 후 `selection_spot_quality`(7.504초). 마지막 응답은 품질 제한을 넘는 AI 선택을 수용하지 않고 기본 추천으로 대체한 결과다. AI 선택 전체 성공으로 보고하지 않는다.
- 별도의 모의 응답을 휴대폰에 주입하지 않았다. 오프라인 자동 검사의 모의 모델과 실제 휴대폰 응답을 혼동하지 않는다.

- 첫 코스의 식당·자연 장소 편중이 남는다. 24개 seed에서 첫 방문 조합은 바른찜갈비→신정호테마공원이었다. 자연 후보는 8개지만 다른 후보들이 현재 품질 허용 폭 밖에 있다.

- AI 후보 비교는 응답이 와도 종류·근거·품질 검사에서 거절되어 기본 추천으로 바뀔 수 있다. 모델 출력만으로 검증 기준을 완화하지 않았다.
